`wan_state_v2_latent_time` + `Wan clean-prefix infill` 当前主线流程图

这张图只对应当前推荐主线，不混入旧版 `frame-time predictor` 或 `latent-only adapter` 方案。核心结构是：先在 Wan latent 时间轴上训练 predictor，导出 `state_tokens`，再用 `I2V clean-prefix` 语义训练 Wan state adapter，最后在正式推理里把 context video 固定成 clean prefix，只补全 future latent。

这页配套说明文档在同目录的 wan_state_v2_mainline_flow.md。如果只抓一句话：当前系统真正要学的是 context video -> future_state_latents -> state_context -> future latent infill 这条链，而不是“先回到原始帧时间轴再做普通视频生成”。

Reading Notes

这里把最容易混淆的 shape 和设计点单独摘出来，浏览图时可以一起看。

1. 两套时间轴

  • K / T 是原始视频帧数，L_ctx / L_future 是 Wan latent 时间步数。
  • predictor v2 已经完全切到 latent-time，所以未来状态 token 是 [B, L_future, D_s]，不是 [B, T, D_s]。

2. Predictor 真正输入什么

  • 主干只看 context_latents + camera_latent + prompt。
  • context_states / future_states 只参与 loss，不进入 predictor 主干前向。

3. 为什么叫 clean-prefix infill

  • Wan 推理初始化时先把总噪声前缀替换成 clean_prefix_latents。
  • 每个 diffusion step 之后再覆盖一次前缀，所以 prefix latent 实际上保持不变。
  • 真正被 scheduler 更新的只有 future 区间。

4. Adapter 训练到底训什么

  • 不是训整个 Wan 主干。
  • 只训练 pipeline.state_adapter 和 DiT 里名字带 state_adapter_ 的注入参数。
  • VAE、text encoder、低噪声和高噪声主模型主体都保持冻结。

5. 正式推理里的状态条件怎么进模型

  • future_state_latents 先重采样到当前 Wan 所需的 L_future。
  • 然后送进训练好的 Wan state adapter，变成 state_context。
  • 再以 adapter / cross-attention memory 的形式进入 Wan DiT。
当前正式推理要求显式提供训练好的 state_adapter_ckpt。如果缺失 checkpoint，流程会直接报错，不再“继续跑但没有真正状态控制”。
