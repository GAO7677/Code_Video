## 父页面 + 子页面结构

- 父页面职责：只做入口汇总，不直接承载大量视频卡片
- 子页面职责：各自维护独立的 `report.json` + `index.html`
- 适用场景：同一专题下需要同时保留全量页、单 case 诊断页、不同版本复查页

### 接入逻辑

- 先分别导出各个子页面目录
- 每个子页面目录内部保持原有静态页结构不变
- 再用 `generate_static_subpage_portal.py` 在父目录生成统一入口 `index.html`
- 最后在父目录启动 `python3 -m http.server`

### 代码位置

- `scripts/generate_static_subpage_portal.py`

## ABD_test 统一入口

- 统一目录默认：`/data/gaoya/AAA_test_video/Output_try0526/ABD_test/_viz_v2`
- 父页面：`/data/gaoya/AAA_test_video/Output_try0526/ABD_test/_viz_v2/index.html`
- 端口：`18885`
- 页面模式：`abd_unified_visualizations`

### 页面职责

- 重构为 `A / B / D` 三组固定目录
- 每组只保留两个页面：
  - `baseline`
  - `training`

### 目录结构

```text
ABD_test/_viz_v2/
  index.html
  A/
    index.html
    baseline/
    training/
  B/
    index.html
    baseline/
    training/
  D/
    index.html
    baseline/
    training/
```

### baseline 页面逻辑

- 从 `ABD_test/A|B|D` 对应组目录直接读取统一后的 case json
- 每组抽取代表性 case
- 每个 case 展示：
  - `Context Image`
  - `Context Video`
  - `GT / Full Video`
  - 所有 baseline 输出视频
- 页面顶部有统一指标表格
- 指标名直接带方向箭头：
  - `↑` 越高越好
  - `↓` 越低越好
- 页面中用中文简要解释每个指标含义

### training 页面逻辑

- 汇总 `phys_state_video` 项目中的主要训练 run
- 每个 run 展示：
  - `best case 页面`
  - `不同 step ckpt 页面`
  - `predictor loss`
  - `adapter loss`
- loss 来自本地训练日志；如存在 `wandb-summary.json`，也会补充显示关键摘要

## 18882 页面

- 目录：`/tmp/bench_json_tailquery_dashboard_18882`
- 页面：`/tmp/bench_json_tailquery_dashboard_18882/index.html`
- 端口：`18882`
- 页面模式：`bench_json_tailquery_dashboard`

### 18882 可视化逻辑

- 这页是 predictor benchmark 页面：
  同一批 predictor 预测结果分别叠在 `Proxy GT` 和 `SAM2 GT` 上做对照。
- `Proxy GT` 直接来自项目内 proxy state。
- `SAM2 GT` 支持两种来源：
  1. 当前环境内直接生成
  2. 从外部缓存读取 `caption_gdino -> SAM2` 结果
- 当需要真正启用 `caption_gdino` 时，推荐使用“两阶段外部缓存”方案：
  `wan-cu128` 先固定 clip；
  `sam` 环境生成 `caption_gdino + SAM2` cache；
  再回到 `wan-cu128` 读取 cache 导出 predictor 页面。

### 18882 两阶段代码位置

- 固定 clip manifest：
  `scripts/export_bench_json_tailquery_manifest.py`
- `caption_gdino + SAM2` cache：
  `scripts/export_bench_json_tailquery_sam2_cache.py`
- predictor dashboard：
  `scripts/export_bench_json_tailquery_dashboard.py`

### 18882 重导命令

说明：

- `ti2v-5B` 当前使用的 `temporal_stride` 是 `4`
- 当前 predictor best ckpt 约束是：
  `max_context_latent_steps=3`
  `max_future_latent_steps=5`
- `caption_gdino` 不能直接在当前 `wan-cu128` 页面导出里跑，是因为本地 `GroundingDINO` 自定义算子和该环境不兼容，所以必须拆成下面三步
- 当前默认目标圈定逻辑是 `caption-first, proxy-fallback`：
  先直接用 `caption -> GroundingDINO` 产出候选框，再交给 `SAM2` 跟踪；只有当 `caption` 为空或 `GDINO` 没检出框时，才退回 `proxy_box_fallback`
- 默认不再使用最近运动轨迹框去过滤 `caption` 候选；如果要恢复旧行为，可额外加 `--caption-use-proxy-guidance`

#### 第一步：固定随机 clip manifest

```bash
source /home/gaoya/miniconda3/etc/profile.d/conda.sh

conda run -n wan-cu128 python /home/gaoya/Code_Video/phys_state_video/scripts/export_bench_json_tailquery_manifest.py \
  --bench-json-root /data/gaoya/AAA_test_video/Output_try0526/bench_jsons_mer \
  --output-json /tmp/tailquery_caption_18882/manifest.json \
  --sample-per-json 5 \
  --json-names A.json B.json D.json \
  --seed 20260606 \
  --height 144 \
  --width 256 \
  --context-min 4 \
  --context-max 12 \
  --future-min 8 \
  --future-max 20 \
  --temporal-stride 4 \
  --max-context-latent-steps 3 \
  --max-future-latent-steps 5
```

作用：

- 固定这次 benchmark 的 source case、clip 起点、context 长度、future 长度
- 保证 `sam` 环境和 `wan-cu128` 环境消费的是完全同一批 clip，而不是各自随机切片

#### 第二步：在 sam 环境生成 `caption_gdino + SAM2` cache

```bash
export CUDA_VISIBLE_DEVICES=4
source /home/gaoya/miniconda3/etc/profile.d/conda.sh

conda run -n sam python /home/gaoya/Code_Video/phys_state_video/scripts/export_bench_json_tailquery_sam2_cache.py \
  --manifest-json /tmp/tailquery_caption_18882/manifest.json \
  --output-dir /tmp/tailquery_caption_18882/sam2_cache \
  --prompt-mode caption_gdino \
  --device cuda
```

作用：

- 默认先用 caption 经过 `GroundingDINO` 生成 prompt boxes
- 再交给 `SAM2` 做整段 clip 的 mask tracking
- 若 `GDINO` 无结果，则自动退回 `proxy_box_fallback`
- 把每个 case 的 `states / boxes / masks / prompt_boxes / primary_idx` 写成 cache

#### 第三步：在 wan-cu128 环境读取 cache 并导出 18882 页面

```bash
export CUDA_VISIBLE_DEVICES=4
source /home/gaoya/miniconda3/etc/profile.d/conda.sh

conda run -n wan-cu128 python /home/gaoya/Code_Video/phys_state_video/scripts/export_bench_json_tailquery_dashboard.py \
  --bench-json-root /data/gaoya/AAA_test_video/Output_try0526/bench_jsons_mer \
  --wan-ckpt-dir /data/gaoya/ckpt/Wan-AI-Wan2.2-TI2V-5B \
  --output-dir /tmp/bench_json_tailquery_dashboard_18882 \
  --manifest-json /tmp/tailquery_caption_18882/manifest.json \
  --sam2-cache-report /tmp/tailquery_caption_18882/sam2_cache/report.json \
  --model-spec tailquery_multictx=/data/gaoya/AAA_test_video/Dataset_physV/phys_state_0601/runs_v2/industrial_s1_scale2_wan_state_v2_tailquery_multictx_gpu0123_20260606/checkpoints/predictor_v2_tailquery_multictx.best.pt \
  --model-spec tailquery_multictx_converge=/data/gaoya/AAA_test_video/Dataset_physV/phys_state_0601/runs_v2/industrial_s1_scale2_wan_state_v2_tailquery_multictx_converge_gpu0123_20260606/checkpoints/predictor_v2_tailquery_multictx_converge.best.pt \
  --sample-per-json 5 \
  --json-names A.json B.json D.json \
  --seed 20260606 \
  --height 144 \
  --width 256 \
  --context-min 4 \
  --context-max 12 \
  --future-min 8 \
  --future-max 20 \
  --fps 6 \
  --port 18882 \
  --wan-repo-root /home/gaoya/Code_Video/Wan2.2-main \
  --wan-task ti2v-5B \
  --device cuda:0
```

作用：

- predictor 页面不再在本环境里直接调用 `GroundingDINO`
- 而是读取第二步落盘的 `caption_gdino -> SAM2` cache
- 最终页面里的 `SAM2 GT` 就是真正 caption 初始化后的时序分割结果
