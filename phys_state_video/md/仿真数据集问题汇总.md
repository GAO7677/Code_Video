# 仿真数据集问题汇总

## 1. Capsule 视觉姿态与物理姿态重复施加

**问题现象**  
部分 `capsule` 视频在某些帧里看起来像有一部分嵌入地面，尤其是在大翻滚姿态和贴地滑行阶段，例如 `simple_f1_capsule_upright_tumble_slide` 这类 case 更容易出现。

**原因**  
渲染 mesh 在 `_make_mesh()` 里先按 `orientation_euler_deg` 预旋转了一次，PyBullet 在 `run_scenario()` 里又把同样的初始姿态作为 `baseOrientation` 施加到刚体上，最后 `PreviewRenderer.update_pose()` 每帧再跟随 body pose 更新节点，导致视觉姿态和物理姿态发生重复叠加。

**解决方案**  
去掉 `_make_mesh()` 里的初始姿态预旋转，让初始朝向只由 PyBullet 的 `baseOrientation` 管理，渲染节点每帧只跟随 PyBullet 返回的 `pos + quat`，这样视觉 mesh 和碰撞体姿态来源保持一致。

**对应文件与函数**  
文件是 [generate_sim_preview_gallery.py](/home/gaoya/Code_Video/phys_state_video/scripts/generate_sim_preview_gallery.py)，关键函数是 `_make_mesh()`、`run_scenario()` 和 `PreviewRenderer.update_pose()`。

## 2. PyBullet 动态 Mesh 碰撞能力边界

**问题现象**  
用户希望所有动态物体都直接使用真实 mesh 做碰撞，但在复杂物体上容易出现“视觉上像某个形状，物理上却不是同一形状”的预期偏差。

**原因**  
当前链路基于 PyBullet，而 PyBullet 更稳定的动态刚体路径是 `sphere / box / cylinder / capsule` 这类 primitive；复杂 mesh 并不等价于“逐三角真实动态碰撞”，所以强行使用会让碰撞行为和直觉不一致。

**解决方案**  
当前阶段把训练用仿真对象收缩到简单刚体，优先保证碰撞形状和视觉形状尽量一致，把复杂动态 mesh 暂时排除在主训练集之外，后续如果要扩展再单独评估引擎和表示方式。

**对应文件与函数**  
文件是 [generate_sim_preview_gallery.py](/home/gaoya/Code_Video/phys_state_video/scripts/generate_sim_preview_gallery.py)，关键函数是 `_make_mesh()`、`_collision_shape()` 和 `build_preview_scenarios()`。

## 3. 可视化服务启动与环境依赖问题

**问题现象**  
有时视频文件已经生成，但本地端口访问失败，或者 `--serve-only` 模式不能正常启动，看起来像是页面坏了，实际上是服务没有起来。

**原因**  
`generate_sim_preview_gallery.py` 即使在 `--serve-only` 模式下也会先 import `cv2` 和 `numpy`，如果系统默认 `python3` 环境缺少这些依赖，脚本会在真正启动静态服务前就失败。

**解决方案**  
重新生成视频时统一使用 `wan` 环境运行脚本；如果只是浏览已有产物，则直接用 `python3 -m http.server` 启动静态服务，不再经过完整生成脚本。

**对应文件与函数**  
文件是 [generate_sim_preview_gallery.py](/home/gaoya/Code_Video/phys_state_video/scripts/generate_sim_preview_gallery.py)，关键函数是 `main()` 和 `start_server()`。

## 4. 纹理下载链路不稳定与本地纹理回退

**问题现象**  
从外部纹理站点直接下载真实木纹时，部分资源会出现 TLS 握手失败、EOF 或下载中断，导致真实材质接入流程不稳定。

**原因**  
问题主要出在当前环境的网络链路稳定性，而不是纹理源本身完全不可用；同一批资源里有的链接能访问，有的会在 `curl` 或 HTTPS 握手阶段失败。

**解决方案**  
优先使用已确认可访问的官方资源；如果外网下载不稳定，则直接回退到本地已有真实纹理目录，例如 `/data/gaoya/dataset/textures/polyhaven_wood/` 和 `/data/gaoya/dataset/blender_render_assets/polyhaven_v1/textures/wood_floor/`，避免让网络问题阻塞渲染迭代。

**对应文件与函数**  
文件是 [generate_sim_preview_gallery.py](/home/gaoya/Code_Video/phys_state_video/scripts/generate_sim_preview_gallery.py)，关键函数是 `_load_texture_rgb()`。

## 5. 纹理映射过于程序化的问题

**问题现象**  
早期预览中的对象表面看起来过于像金属块、木块或程序噪声贴色，虽然稳定，但视觉上比较假，也不利于后续模拟更真实的训练材质分布。

**原因**  
初始实现主要依赖顶点色、正弦条纹、程序噪声和简单 checker，这些方法成本低，但表面细节单一，缺少真实纹理频率和材质变化。

**解决方案**  
先增加 `painted / stripe / two_tone / label / plastic` 这类程序化材质，再接入真实木纹纹理，并通过轻量三平面近似采样把纹理转换为顶点色，从而在不引入完整 UV/PBR 流程的前提下提升表面真实性。

**对应文件与函数**  
文件是 [generate_sim_preview_gallery.py](/home/gaoya/Code_Video/phys_state_video/scripts/generate_sim_preview_gallery.py)，关键函数是 `_apply_procedural_material()`、`_load_texture_rgb()`、`_sample_texture()`、`_textured_vertex_colors()`、`_apply_industrial_theme()` 和 `_apply_daily_theme()`。
