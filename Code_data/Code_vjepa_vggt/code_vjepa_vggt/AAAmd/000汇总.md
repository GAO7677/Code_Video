## 1. 当前默认目标

当前默认分支的目标不是训练主去噪路径，而是先把 object branch 本身训练稳定，让它能够更可靠地回归：

- `track`
- `box`
- `depth`

所以默认 head-only 训练里：

- `lambda_main = 0.0`
- `lambda_track_aux = 0.1`
- `lambda_box_aux = 0.1`
- `lambda_depth_aux = 0.1`

这意味着：

- `loss_main` 不参与回传
- 实际更新的是 object branch 和 aux heads
- W&B 里需要重点看：
  - `train/loss_total`
  - `train/loss_track_aux`
  - `train/loss_box_aux`
  - `train/loss_depth_aux`
  - `train/object_context_abs_max`
  - `train/object_latent_tokens_abs_max`

## 3. 数据输入与 sample 结构

默认数据集实现是：

- [phys_state_dataset.py](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/data/phys_state_dataset.py)

对于一条样本，数据集会从 `episodes_v1/*.npz` 中读取：

- `context_frames`
- `future_frames`
- `context_boxes`
- `future_boxes`
- `context_states`
- `future_states`

### 3.1 原始窗口长度

默认这套 `phys_state_episode` 数据里，一个窗口是：

- `context_frames`: `T_ctx = 8`
- `future_frames`: `T - T_ctx = 16`

所以总窗口长度记作：

- `T = 24`

这里后文统一用：

- 原始视频时间轴写 `T`
- context 时间轴写 `T_ctx`
- latent 时间轴写 `T_lat`
- 其他维度用具体数值

### 3.2 训练 sample 的主要张量

数据集返回的核心字段是：

- `video`:
  - `[3, T, 512, 896]`
- `context_video`:
  - `[3, T_ctx, 512, 896]`
- `context_boxes`:
  - `[T_ctx, 6, 4]`
- `context_states`:
  - `[T_ctx, 6, state_dim]`
- `future_boxes`:
  - `[T - T_ctx, 6, 4]`
- `future_states`:
  - `[T - T_ctx, 6, state_dim]`

说明：

- 数据集中一个样本原始 GT 物体数通常是 `6`
- 但默认训练时真正保留的 object 槽位是 `4`

### 3.3 默认 context 采样方式

当前默认分支不是随机 context，而是固定取前 `8` 帧：

- `random_context_frames = False`

所以当前默认训练和 val loss 口径是一致的：

- 都使用窗口前 `T_ctx = 8` 帧 context

## 4. query prior 构造

当前 object branch 使用 GT box 构造 query prior。

默认配置：

- `aux_max_objects = 4`
- `object_num_queries = 8`

所以：

- 物体槽位数 `O = 4`
- 每个物体点数 `Q = 8`
- 总 query 点数 `O * Q = 32`

构造后的核心张量是：

- `query_points_prior`:
  - `[1, 32, 2]`
- `query_frame_ids`:
  - `[1, 32]`
- `object_valid_mask`:
  - `[1, 4]`
- `box_prior_xyxy`:
  - `[1, 4, 4]`

语义：

- 每个有效物体槽位提供 `8` 个 query 点
- 无效槽位后续由 `object_valid_mask` 屏蔽

---

## 5. CoTracker 轨迹分支

默认 query prior 会送入 CoTracker：

- `context_video` 先转成 `[1, T_ctx, 512, 896, 3]`
- CoTracker 对 `32` 个 query 点做跟踪

CoTracker 输出的点级结果是：

- `tracks`:
  - `[1, T_ctx, 32, 2]`
- `visibility`:
  - `[1, T_ctx, 32]`
- `confidence`:
  - `[1, T_ctx, 32]`

再按物体分组后得到：

- `tracks_grouped`:
  - `[1, T_ctx, 4, 8, 2]`
- `visibility_grouped`:
  - `[1, T_ctx, 4, 8]`
- `confidence_grouped`:
  - `[1, T_ctx, 4, 8]`

这里的语义是：

- 第 3 维是物体槽位 `4`
- 第 4 维是每个物体的 `8` 个 query 点

---

## 6. JEPA / latent / motion / geometry 四路信息

当前默认 object pooler 会综合四类信息：

- `JEPA appearance`
- `Wan latent appearance`
- `CoTracker motion`
- `VGGT geometry`

这部分实现主要在：

- [object_tokens.py](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/models/object_tokens.py)

### 6.1 JEPA appearance

JEPA 从 `context_video` 中提 patch token。

进入 object pooler 的是：

- `jepa_patch_tokens`:
  - `[1, T_ctx, H_j, W_j, C_jepa]`

沿 CoTracker 轨迹在 JEPA feature map 上采样并聚合后，得到：

- `jepa_latent_tokens`:
  - `[1, T_lat, 4, 4096]`

这里：

- `T_lat` 是 latent 时间长度
- 当前默认 `T_ctx = 8`
- 当前默认 `T_lat = 2`
- 所以后续所有 head 监督实际都落在 `T_lat = 2`

### 6.2 Wan latent appearance

生成模型自身的 context latent 也会沿轨迹采样。

默认 `context_latents` 形状是：

- `[1, 16, T_lat, 64, 112]`

采样聚合后得到：

- `latent_latent_tokens`:
  - `[1, T_lat, 4, 4096]`

### 6.3 motion

CoTracker 轨迹会构造成 motion 属性：

- `x`
- `y`
- `dx`
- `dy`
- `vis`
- `conf`

点级 motion 特征是：

- `motion_local`:
  - `[1, T_lat, 4, 8, 6]`

经过投影和点内 attention pooling 后得到：

- `motion_latent_tokens`:
  - `[1, T_lat, 4, 4096]`

### 6.4 VGGT geometry

当前默认分支优先走离线 VGGT cache，而不是在线 VGGT。

读取根目录：

- `/data/gaoya/AAA_test_video/0623/train/train0624/vggt_cache`

默认用到的几何输入包括：

- `dense_patch_tokens`
- `depth`
- `depth_conf`
- `world_points`
- `world_points_conf`

沿 CoTracker 轨迹在 VGGT 几何图上采样后，几何分支会形成：

- `geom_latent_tokens`:
  - `[1, T_lat, 4, 4096]`

以及单独的 depth token：

- `depth_latent_tokens`:
  - `[1, T_lat, 4, 4096]`

说明：

- 当前默认训练 supervision 用的 depth GT 不是 VGGT depth
- `vggt_depth` 是 object pooler 的几何输入之一
- 它不是 `loss_depth_aux` 的 GT

## 7. 当前默认 object token 融合逻辑

默认 object branch 不是旧的多路并联大杂烩，而是精简成两路主干融合：

- `track + geometry`
- `appearance`

更具体地说：

### 7.1 track + geometry 路

这一支综合：

- `motion_latent_tokens`
- `geom_latent_tokens`
- `active_track_summary` 派生出的 track geometry token

最终形成：

- `track_geom_latent_tokens`:
  - `[1, T_lat, 4, 4096]`

### 7.2 appearance 路

这一支综合：

- `jepa_latent_tokens`
- `latent_latent_tokens`

最终形成：

- `appearance_latent_tokens`:
  - `[1, T_lat, 4, 4096]`

### 7.3 最终 object latent token

两路融合后得到主 object token：

- `object_latent_tokens`:
  - `[1, T_lat, 4, 4096]`

默认 `T_lat = 2`，所以实际是：

- `[1, 2, 4, 4096]`

这就是后续：

- `object_aux_heads`
- `object_adapter`

共同消费的核心 object 表征。

## 8. active track / active box

在 object token 之外，pooler 还会输出当前 active 轨迹与 active box。

### 8.1 active track summary

默认输出：

- `active_track_summary`:
  - `[1, T_lat, 4, 4]`

4 个通道语义是：

- `center_x`
- `center_y`
- `delta_x`
- `delta_y`

### 8.2 active box

默认输出：

- `active_box_xyxy`:
  - `[1, T_lat, 4, 4]`

4 个通道语义是：

- `x0`
- `y0`
- `x1`
- `y1`

它来自轨迹和 prior box 的组合，是当前 box head 的几何锚点。

## 9. object aux heads

默认 object aux heads 实现在：

- [object_aux_heads.py](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/models/object_aux_heads.py)

输入是：

- `object_latent_tokens`:
  - `[1, T_lat, 4, 4096]`
- `active_track_summary`:
  - `[1, T_lat, 4, 4]`
- `active_box_xyxy`:
  - `[1, T_lat, 4, 4]`

输出是：

- `pred_track_summary`:
  - `[1, T_lat, 4, 4]`
- `pred_box_xyxy`:
  - `[1, T_lat, 4, 4]`
- `pred_box_wh`:
  - `[1, T_lat, 4, 2]`
- `pred_depth`:
  - `[1, T_lat, 4, 1]`

说明：

- `track head` 预测的是对 `active_track_summary` 的残差
- `box head` 预测的是对 `active_box_xyxy` 的残差
- `depth head` 直接从 `object_latent_tokens` 回归 depth 标量

## 10. object adapter 与 Wan 注入

默认虽然 `lambda_main = 0.0`，但 object adapter 仍然会构建出注入张量：

- `object_context`

它来自：

- `object_latent_tokens [1, T_lat, 4, 4096]`

再经过 adapter 后送入 Wan 的 object injection branch。

当前 head-only 默认训练里：

- 这条注入链路存在
- 但因为 `loss_main = 0.0`
- 主去噪路径不参与梯度主导

所以当前阶段真正核心还是 aux heads 的监督稳定性。

## 11. 默认 GT 对齐与监督构造

当前默认 supervision 不是直接按槽位顺序硬对齐，而是先做轨迹到 GT box 的匹配。

匹配逻辑核心是：

- CoTracker 中心轨迹
- 与 `context_boxes` 做对齐
- 形成 `track_alignment`

关键输出是：

- `matched_gt_indices`:
  - `[1, 4]`
- `matched_gt_centers`:
  - `[1, T_ctx, 4, 2]`
- `matched_gt_valid`:
  - `[1, T_ctx, 4]`

然后进一步得到：

- `matched_gt_boxes`:
  - `[1, T_ctx, 4, 4]`

再按 latent 时间轴聚合：

- `gt_track_summary`:
  - `[1, T_lat, 4, 4]`
- `gt_box_xyxy`:
  - `[1, T_lat, 4, 4]`
- `gt_box_valid`:
  - `[1, T_lat, 4]`

默认 `T_lat = 2`。

## 12. 默认 depth GT 方案

当前默认 depth GT 来源是：

- `depth_target_source = depth_anything_box`

这条默认分支使用的是 compact box cache。

### 12.1 默认读取顺序

训练在 `_build_depth_targets(...)` 中默认读取：

- `*.depth_anything_box.pt`

### 12.2 默认 compact cache 的内容

当前推荐的 compact cache 文件是：

- `sample_xxxxxx_wyyy.depth_anything_box.pt`

它内部保存的是：

- `depth_boxes_framewise`:
  - `[T_ctx, 6, 1]`

语义：

- `T_ctx = 8` 是 context 帧数
- `6` 是原始 GT 物体数
- 每个物体在每帧只保留一个 depth scalar

这个 scalar 的计算方式是：

- 先对 `context_frames` 跑 Depth Anything
- 得到 `depth map`
- 再在 `GT box` 内取 depth median

训练时再做两步：

1. 按 `matched_gt_indices` gather 出默认 `4` 个物体槽位
2. 再做 `group_last(...)`，变成 latent 时间轴监督

最终默认进入 `depth head` 的 GT 形状是：

- `gt_depth`:
  - `[1, T_lat, 4, 1]`

默认 `T_lat = 2`，也就是：

- `[1, 2, 4, 1]`

## 17. 默认方法一句话总结

当前默认分支可以概括为：

- 用 `8` 帧 context video 和 GT box 构造 `32` 个 query prior
- 用 `T_ctx = 8` 帧 context video 和 GT box 构造 `32` 个 query prior
- 用 CoTracker 得到物体轨迹
- 用 JEPA / Wan latent / motion / VGGT geometry 四路信息沿轨迹采样
- 融合成 `[1, T_lat, 4, 4096]` 的 object latent tokens
- 用 aux heads 在 latent 时间轴上回归：
  - `track`
  - `box`
  - `depth`
- 其中默认 depth GT 来自离线 `Depth Anything + GT box median pooling` 的 compact cache

## 附加说明：非默认备选分支

下面这些不是当前默认主线，只作为附加说明保留。

### A. `state` depth GT 分支

- `depth_target_source = state`
- 直接从：
  - `context_states[..., depth_target_state_index]`
  取 depth GT
- 不依赖任何 `.pt`

适用情况：

- 想快速开训
- 不想等 Depth Anything cache

### B. 旧的 full-frame `depth_anything.pt` 分支

- 先离线存整帧 depth：
  - `depth_frames [T_ctx, 144, 256]`
- 训练时再在线按 box 做 pooling

当前仍保留兼容回退，但不再是默认主线。

### C. `SAM mask pooling` depth GT 分支

当前已经验证过一个原型脚本：

- [compare_depth_gt_sam_mask_pool.py](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/compare_depth_gt_sam_mask_pool.py)

它的思路是：

- 用 GT box 提示 SAM2 image predictor
- 得到每帧对应的 `SAM mask`
- 不在 GT box 内池化 depth
- 改为在 `SAM mask` 内做 median pooling

这条路线目前只完成了可视化与单 case 对比验证，还没有接成默认训练分支。

### D. online Depth Anything 分支

也可以不依赖 cache，在训练时在线跑 Depth Anything，再在线构建 depth GT。

这条路线目前不是默认方案，因为：

- step time 会明显上升
- 会带来额外显存和调度压力

当前更稳的默认主线仍然是：

- 离线 compact cache

### E. Stage2 冻结 head、训练 object 注入链路

这也是一个已有实验分支，但不是当前默认 head-only 方案。

它的目标是：

- 冻结已经稳定的 `object_pooler + object_aux_heads`
- 只训练：
  - `object_adapter`
  - Wan DiT object 注入链路

它属于后续阶段，不属于当前这份默认 head-only 汇总正文。
