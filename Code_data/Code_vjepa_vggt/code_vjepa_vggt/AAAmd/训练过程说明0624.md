# 训练过程说明 0624

## 1. 为什么有时只看到两帧

- 当前训练可视化页不是直接把 8 帧原始 context video 全部铺开，而是按 `latent_frames` 做对齐后再渲染。
- 在 `inspect_train_aux_losses_v_newtrain_compare.py` 里，`_render_box_overlay(...)` 和 `_render_track_overlay(...)` 都先取 `latent_frames = gt_box_xyxy.shape[0] / gt_track_summary.shape[0]`，然后把每个 latent step 映射回一帧代表图。
- 当 8 帧 context 经过 VAE 时间压缩后只对应 2 个 latent step 时，页面就只会显示 2 帧代表图，不是原视频只剩 2 帧。
- 当前实现里，如果 `source_frames % latent_frames == 0`，会取每个组里的最后一帧做代表帧，所以 8 帧上下文常会显示成 2 帧。

## 2. 黄色点、蓝色点、黄色框、蓝色框分别是什么

- `inspect_train_aux_losses_v_newtrain_compare.py`
  - `GT track` 是橙色
  - `Pred track` 是蓝色
  - `GT box` 是红色
  - `Pred box` 是青绿色
- 也就是说，这个训练 loss 对比页里，颜色语义是固定的 `GT / Pred`，不是对象编号颜色。
- 如果你看到的是多对象可视化页 `eval_vggt_sam_multi_object_viewer.py`
  - 每个 object slot 会用自己的对象颜色
  - 黄色、蓝色这类颜色只是不同对象槽位的区分
  - `fix` 标记的黄色点 `(255,255,0)` 表示被 correction step 修正后的轨迹点，不是 GT
  - 这个页面里的 `GT box` 仍然是白色，`pred/sam` box 才是对象槽位颜色

## 3. 这次异常的初步结论

- 当前 `pybullet0624_diffsynth_object_v_newtrain_gpu67` 的异常更像是“对象 prior / track 对齐”出了问题，而不是单纯 loss 权重不够。
- 现象包括：
  - `train/object_context_abs_max` 持续变大
  - `pred box` 明显偏大，且左上角偏移明显
  - `pred track` 和 `GT track` 位置不一致
  - 可视化里有一些点落到画面左上角
- 后续需要重点核查：
  - query prior 是从哪一帧采样出来的
  - CoTracker 的 query frame id 是否和 prior 来源帧一致
  - object summary 到 box 的回归是否在奖励“贴近左上角的退化解”

## 4. 当前修复方案

- 已做的关键修复
  - `CoTrackerAdapter` 增加 `query_frame_ids` 可选输入，默认仍兼容旧行为
  - `train_v_newtrain.py` 的 object query prior 改为“每个 object 的第一帧有效 box”
  - `object_condition_adapter` 在 adapter 后按 `object_valid_mask` 屏蔽无效 slot
  - `object_tokens._track_summary(...)` 改成按有效帧挑选首尾，而不是硬取 group 边界
  - `object_context_abs_max` 改为只统计有效 slot
- 这样做的目标
  - 让 query prior / query 起点 / track summary 使用同一套时间语义
  - 避免无效 slot 在 adapter 里被时间/slot embedding 重新激活
  - 降低 `pred box` 左上角退化和 track 偏移

## 7. 这次新修复的重点

- 旧问题
  - `active_box_xyxy` 过去是固定 `12px` 的中心框 prior，尺度过小
  - `pred_box_xyxy` 又是围绕这个过小 prior 做 residual 回归，导致 box 尺寸长期偏小
  - `pred_track_summary` 还会把 box center 一起带偏，形成 track / box 同向漂移
- 这次改动
  - `query prior` 继续从每个 object 的首个有效 context box 采样 8 个点
  - 新增 `box_prior_xyxy`，直接把对象的首个有效 context box 作为 box prior
  - `ObjectTubeProjector` 优先使用 `box_prior_xyxy`，不再固定用 12px 小框
  - `ObjectAuxHeads` 的 box center residual 改为相对 prior center 的小偏移，box size 改为 log-space residual，扩大可恢复的尺寸范围
- 预期效果
  - `active_prior` 的宽高应该更接近 GT box
  - `pred box` 不再被锁死在过小尺寸
  - `pred track` 与 `GT track` 的中心偏移应明显减弱
  - `object_context_abs_max` 仍然可能在 4 左右波动，这本身不一定是异常，关键是 box/track 可视化是否稳定
- 验证方式
  - 先跑 smoke
  - 再看 `smoke_report.json` 里的 `box_stats` / `track_stats`
  - 再开 `inspect_train_aux_losses_v_newtrain_compare.py` 看 overlay 是否还在左上角退化
