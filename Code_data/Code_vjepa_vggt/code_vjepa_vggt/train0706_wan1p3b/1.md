**主 pipeline 一次前向的完整 shape 流**

真正的 pipeline 前向在 [context_wan_v_newtrain.py:858](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L858)。

先看 shape checker 和 noise 初始化：

- `num_frames=24` 被 round 到 `25`
- Wan 的 latent 时间长度公式在 [wan_video.py:245](/home/gaoya/Code_Video/WAN_2p2/DiffSynth-Studio-main/diffsynth/pipelines/wan_video.py#L245) 的 `WanVideoUnit_NoiseInitializer` 里：
  `length = (num_frames - 1) // 4 + 1`
- 所以这次 `length = (25 - 1)//4 + 1 = 7`

于是初始化噪声 latent 的 shape 是：

- `noise`: `[1, 48, 7, 32, 56]`

这里：
- `1` 是 batch
- `48` 是 Wan VAE latent channel
- `7` 是 latent 时间长度
- `32 = 512 / 16`
- `56 = 896 / 16`

然后 `WanVideoUnit_InputVideoEmbedder` 先运行。因为你这次 `input_video=None`，所以它直接把：

- `latents = noise = [1, 48, 7, 32, 56]`

逻辑在 [wan_video.py:396](/home/gaoya/Code_Video/WAN_2p2/DiffSynth-Studio-main/diffsynth/pipelines/wan_video.py#L396)。

接下来是这个项目自己插进去的 `WanVideoUnit_ContextVideoEmbedder`，见 [context_wan_v_newtrain.py:305](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L305)。它把 `context_video` 编码成：

- `clean_prefix_latents = [1, 48, 2, 32, 56]`

然后把它覆盖进 `latents` 的前两帧 latent 时间步：

- 输入前 `latents`: `[1, 48, 7, 32, 56]`
- 覆盖后 `latents`: 仍然是 `[1, 48, 7, 32, 56]`
- 只是 `t=0,1` 这两步变成 clean context latent，`t=2..6` 仍是噪声

也就是说，这个 pipeline 不是把上下文视频当成 `input_video` 去做视频编辑，而是把上下文当成 prefix latent 固定住，让模型只生成后面的未来 latent。

之后进入每个 diffusion step 的 `model_fn_wan_video_with_context`，在 [context_wan_v_newtrain.py:365](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L365)。

这一步里面最重要的 shape 变化是：

- 输入 `latents`: `[1, 48, 7, 32, 56]`
- 因为有 `clean_prefix_latents`，会先再次把 prefix 覆盖回去，见 [context_wan_v_newtrain.py:478](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L478)
- `context` 文本条件在进入 `dit.text_embedding` 之前，可以理解成 `[1, L_text, 4096]`
- `dit.text_embedding(context)` 之后变成 `[1, L_text, 3072]`，见 [context_wan_v_newtrain.py:526](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L526)
- 这里 `L_text` 取决于 tokenizer 后 prompt 长度，这次代码没有把它打印出来，所以只能确定“维度是 3072，序列长度是 prompt-dependent”

然后是 patchify，这一步很关键。Wan 这版 DiT 的 patch size 从加载日志里可以看到是 `[1,2,2]`，也就是只在空间上做 `2x2` patch，时间不压。于是：

- 输入 `x = latents`: `[1, 48, 7, 32, 56]`
- `dit.patchify(x)` 后，`f,h,w` 变成：
  - `f = 7`
  - `h = 16`
  - `w = 28`
- 所以 patchify 后可以理解成：
  - `x`: `[1, 3072, 7, 16, 28]`

这对应代码 [context_wan_v_newtrain.py:549](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L549) 到 [context_wan_v_newtrain.py:559](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L559)。

接着把 3D patch grid 展平成 token sequence：

- `x = rearrange(x, "b c f h w -> b (f h w) c")`
- 所以 `x`: `[1, 3136, 3072]`

因为：
- `3136 = 7 * 16 * 28`

同时，`object_context` 在送进 block 前，会先走 `dit.object_embedding`，见 [context_wan_v_newtrain.py:701](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L701)：

- 原始 `object_context`: `[1, 8, 4096]`
- 经过 `dit.object_embedding` 后：`[1, 8, 3072]`

这一步的意义很直接：把对象 token 从 text-dim 4096 映射到 DiT hidden dim 3072，才能和视频 token 做 cross-attention。

然后每个 Transformer block 内部的 shape 维持不变，见 object branch 注入逻辑 [context_wan_v_newtrain.py:95](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L95) 和实际调用 [context_wan_v_newtrain.py:760](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L760)：

- block 输入 `x`: `[1, 3136, 3072]`
- text cross-attn 的 key/value: `[1, L_text, 3072]`
- object cross-attn 的 key/value: `[1, 8, 3072]`
- block 输出 `x`: 仍然 `[1, 3136, 3072]`

可以把 object 注入理解成：

- 先正常做 self-attn / text cross-attn / FFN
- 再额外做一次 `object_cross_attn(norm4(x), object_context)`
- 得到 `object_delta: [1, 3136, 3072]`
- 用 `tanh(object_gate)` 缩放后加回 `x`

全部 block 走完之后，DiT head 和 unpatchify 把 token sequence 还原回 latent 网格，见 [context_wan_v_newtrain.py:794](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L794) 到 [context_wan_v_newtrain.py:805](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L805)：

- block stack 输出 `x`: `[1, 3136, 3072]`
- `dit.unpatchify(x, (f,h,w))`
- 最终 `noise_pred`: `[1, 48, 7, 32, 56]`

这也是为什么 scheduler 的输入输出都保持 latent shape 不变：

- `inputs_shared["latents"]`: `[1, 48, 7, 32, 56]`
- `noise_pred`: `[1, 48, 7, 32, 56]`
- `scheduler.step(...)` 后新 `latents`: `[1, 48, 7, 32, 56]`

并且在每一步 scheduler 更新后，prefix 会被再次强制写回 clean latents，见 [context_wan_v_newtrain.py:1049](/home/gaoya/Code_Video/Code_data/Code_vjepa_vggt/code_vjepa_vggt/context_wan_v_newtrain.py#L1049)：

- 每一步都保证 `latents[:, :, :2] = clean_prefix_latents`

所以这次 12-step 采样的真实语义是：

- 前 2 个 latent 时间步固定为上下文
- 后 5 个 latent 时间步被逐步去噪生成

最后 decode：

- 输入 decode 的 `latents`: `[1, 48, 7, 32, 56]`
- `vae.decode(...)` 后得到视频 tensor，语义上是 `[1, 3, 25, 512, 896]`
- `vae_output_to_video(...)` 把它变成 `25` 张 `PIL.Image`，见 [base_pipeline.py:144](/home/gaoya/Code_Video/WAN_2p2/DiffSynth-Studio-main/diffsynth/diffusion/base_pipeline.py#L144)

**把这次 forward 压成一条 shape 链**

这次 case 的完整 shape 链，可以直接写成：

```text
mp4
-> read_video_prefix
-> frames: [8, H0, W0, 3]

-> preprocess_video_rgb_uint8
-> context_video_single: [3, 8, 512, 896]

object branch:
[3,8,512,896]
-> unsqueeze
-> [1,3,8,512,896]
-> viewer grounding
-> query_points [1,32,2], frame_ids [1,32,1], valid_mask [1,4], boxes [1,4,4]
-> CoTracker
-> tracks [1,8,32,2]
-> VAE encode(context)
-> clean_prefix_latents [1,48,2,32,56]
-> object_pooler
-> object_latent_tokens [1,2,4,4096]
-> object_adapter
-> object_context [1,8,4096]

main pipeline:
prompt + context_video(list[PIL]*8) + object_context[1,8,4096]
-> shape checker: num_frames 24 -> 25
-> noise init
-> latents/noise [1,48,7,32,56]
-> context embedder
-> clean_prefix_latents [1,48,2,32,56]
-> overwrite prefix
-> latents [1,48,7,32,56]

per denoise step:
latents [1,48,7,32,56]
-> patchify
-> [1,3072,7,16,28]
-> flatten tokens
-> [1,3136,3072]

text context:
prompt
-> text encoder / text_embedding
-> [1,L_text,3072]

object context:
[1,8,4096]
-> object_embedding
-> [1,8,3072]

DiT blocks:
x [1,3136,3072]
+ text cross-attn([1,L_text,3072])
+ object cross-attn([1,8,3072])
-> x [1,3136,3072]

-> head + unpatchify
-> noise_pred [1,48,7,32,56]
-> scheduler.step
-> latents [1,48,7,32,56]
-> restore prefix [:,:, :2]

after 12 steps:
latents [1,48,7,32,56]
-> VAE decode
-> video tensor [1,3,25,512,896]
-> vae_output_to_video
-> list[PIL.Image] len=25
```

**两个容易误解的点**

- `context_video` 不是直接当 `input_video` 做 v2v 编辑。这里它的作用是生成 `clean_prefix_latents`，只固定前缀时间步。
- `object_context` 不是和视频 latent 拼接，而是在每个 DiT block 里额外做一次 object cross-attention。
