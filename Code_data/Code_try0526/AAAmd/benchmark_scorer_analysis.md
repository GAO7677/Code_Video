# Benchmark 与 Scorer 简析

本文只基于当前仓库代码和已有结果文件。能形成稳定结论的主体是 `PDI-Bench` 与 `Dataset_physV(ABC)`；`Physics-IQ` 当前在本项目里还没有完整跑齐，只适合描述数据集结构，不适合下方法优劣结论。

## Benchmark

### PDI-Bench

PDI-Bench 在当前项目里承担的是“真实视频与生成视频方法对比集”的角色。它以自然视频为主，场景里同时包含物体运动、遮挡、纹理、镜头运动和感知前端稳定性，因此更适合看整体几何一致性，不适合直接当作纯受控物理实验。

- 当前项目实际使用 `15` 个 case、`4` 个方法，共 `60` 个视频。
- 子类分布为：`partial_occlusion 16`、`Biological_Motion 12`、`Dynamic_Tracking 12`、`Longitudinal_Convergence 12`、`Curved_Motion 8`。
- 自然场景复杂，能暴露感知前端、几何一致性和视频生成质量的综合问题。


### Dataset_physV

Dataset_physV 是自建的 PyBullet 仿真评测集。固定场景、单次改变某一类参数。

#### B1 物理参数

B1 是 `8` 个 ball-block 刚体碰撞视频，固定相机、背景、光照、重力、初速度和木块质量，只改变碰撞相关物理参数。

- 恢复系数 `e`：`0.3 / 0.5 / 0.7 / 0.9`
- 摩擦系数 `mu`：`0.1 / 0.5 / 1.0`
- 球质量：`0.1 / 1.0 / 5.0 kg`
- 固定条件：球初速度约为 `vx=3.5, vz=1.8 m/s`，重力 `9.81 m/s²`，木块质量 `1.5 kg`

这组数据主要看指标能否对碰撞弹性、滑动阻力和球体惯性做出响应。

#### B2 运动敏感性

B2 是 `20` 个系统参数扫描视频，在**固定外观**下逐项改变动力学条件。

- 速度扫描：`0.5 / 1.5 / 3.5 / 7.0 / 14.0 m/s`
- 球质量扫描：`0.01 / 0.05 / 0.1 / 1 / 5 / 20 / 100 kg`
- 重力扫描：`4.9 / 9.81 / 19.6 m/s²`
- 木块质量扫描：`0.5 / 5 / 20 kg`
- 额外条件：
  - `nomiss`：把木块移开，形成“不碰撞”视频
  - `rev_035`：把球放到右侧，以 `-3.5 m/s` 反向撞击

这组数据主要看指标对速度、质量、重力、碰撞发生与否、运动方向变化是否敏感。

#### B3 外观敏感性

B3 是 `24` 个重渲染视频，物理轨迹与 B1 保持一致，只改渲染外观，用来检查指标是否把视觉风格误判成物理差异。

- 物理部分沿用 B1 的 `8` 条轨迹
- 每条轨迹渲染成 `3` 个外观版本：
  - `v1_default`：橙色球、棕灰地板、暖白聚光、常规亮度
  - `v2_dark_blue`：蓝色球、深色背景、冷色光、更暗环境、更强灯光
  - `v3_warm_bright`：绿色球、暖色背景、更亮环境、暖黄光
- 相机位置与物理参数不变

这组数据专门用来区分“指标在看物理”还是“指标在看颜色、亮度、背景和光照”。

#### C 帧序打乱

C 是时序 sanity check。它不改单帧内容，只打乱帧顺序，用来检查指标是否真的依赖正确时间结构。

- 当前可配对 `20` 对样本
- 其中包含 `10` 个 GT 视频打乱样本和 `10` 个仿真视频打乱样本
- 目录中显式保存了 `20` 个 `*_shuffled` 和 `1` 个 `gt_ball_original`；其余原始视频需要回到 A/B 根目录配对

如果一个指标在 C 组上对打乱前后几乎无变化，或者打乱后反而更好，就不能把它当作可靠的时序物理指标。

### Physics-IQ

Physics-IQ 覆盖的现象范围更广，包含刚体碰撞、流体、光学、热学、磁学等内容。

- 当前 GT 集有 `66` 个 case
- 类别分布为：`Solid Mechanics 38`、`Fluid Dynamics 15`、`Optics 8`、`Thermodynamics 3`、`Magnetism 2`
- 当前项目里 `4-way` 完整覆盖只有 `23/66`
- `result/method_metrics_summary.csv` 目前还是 `1` 个 case 的 smoke 结果


## Scorer

### Official PDI

Official PDI 是 PDI-Bench 的官方几何审计分数，核心依赖分割、跟踪、深度和投影一致性，用来判断目标运动在几何上是否自洽。

- 当前代码直接读取 `metric_results.official_pdi`
- 主指标是 `pdi_score ↓`
- 当前这批结果里 `traj_component` 基本恒为 `0.0`，实际起主要作用的是 `scale / rigidity / vp`
- B3 中同一物理轨迹仅换外观，`PDI` 仍可变化 `5.3x ~ 12.6x`
- C 组 `20` 对样本里有 `17` 对在打乱后分数反而更好

它更像“几何前端稳定性 + 局部结构一致性”指标，不适合直接当作时序物理正确性分数。

### WMReward Surprise

WMReward Surprise 对应官方 `compute_wmreward.py` 的默认分数，本质是基于 V-JEPA 的滑窗未来预测误差。当前项目已经统一到官方默认 CLI 口径，主看 `surprise ↓`。

- A 组四个方法均值只在 `0.42696 ~ 0.43065` 之间
- B1 跨度 `0.0184`
- B2 跨度 `0.0255`
- C 组 `20` 对里有 `19` 对打乱后变差，但平均只恶化 `0.0181`

它能反映局部时序预测难度，但区分度偏弱。

### V-JEPA Proxy

V-JEPA Proxy 是项目内自定义的代理指标，不走官方 benchmark。它比较“给定上下文后模型预测的未来结构”和“候选视频真实未来结构”之间的误差。

- 当前更应该看三个展开项：`RelRaw / DeltaRel / DeltaProf`
- 兼容字段里的总分只是 `exp(-(三项误差之和))`，不建议再作为主结论
- A 组里它的子指标会出现分裂：例如 `RelRaw` 更偏向部分生成视频，而 `DeltaRel` 更接近 GT
- C 组中 `RelRaw` 平均只恶化 `0.0071`

它更适合做“未来结构预测是否一致”的诊断，不适合直接等价为物理合理性评分。

### Cosmos Reason1

Cosmos Reason1 是 Cosmos cookbook 里的 LLM judge 分数，模型直接看视频并按固定 prompt 输出 `1` 到 `5` 的离散物理合理性评分。

- 优点是可解释，适合和文本理由一起读
- B1 上 `8` 个样本全部打 `2`
- B3 中仅外观变化就可能从 `1` 跳到 `5`
- C 组 `20` 对里有 `14` 对完全不变

它适合抓明显违和样本，不适合细粒度定量排序。

### VideoPhy-2

VideoPhy-2 是离散式自动评测器。当前项目主要使用两个子分数 `SA` 和 `PC`，以及一个简单通过率 `Joint = 1[SA>=4 且 PC>=4]`。

- A 组里 GT 的 `PC=4.13`、`Joint=0.73` 都最高
- B1 上 `PC` 全为 `4`，`Joint` 全为 `0`
- B2 上也有明显饱和
- C 组中 `PC` 从不在打乱后变高，但多数样本保持不变

它更像粗粒度 judge，适合判断明显错误，不适合在相近样本之间做细排。

## 分析

### 指标本身的结论

- `Official PDI` 在 B1/B2 上有较大数值波动，但 B3 和 C 说明它对外观与时序都不稳，不能直接解释成纯物理分数。
- `WMReward Surprise` 在 C 组方向基本正确，但 A/B 组区分度很小，更像短窗预测难度。
- `V-JEPA Proxy` 有一定时序方向性，但信号弱，而且会偏好更平滑、更容易预测的未来。
- `Cosmos Reason1` 和 `VideoPhy-2` 都能提供可解释的粗粒度判断，但分数离散，且容易受视觉呈现影响。

### 从指标反推 benchmark 的缺陷

#### PDI-Bench

- 它适合比较“真实视频 vs 生成视频”的整体质量，不适合被解释成纯物理 benchmark。
- 证据是 A 组里 GT 在 `PDI / Cosmos / VideoPhy-2` 上整体更优，但 `WMReward` 基本打平，`V-JEPA Proxy` 的部分子项还会偏向生成视频。
- 这说明 benchmark 中混入了可预测性、纹理复杂度、跟踪难度和前端感知误差。

#### Dataset_physV

- B 组受控性强，但场景过窄，基本是单相机、单球、单木块的 toy setup。
- B3 证明很多分数会把颜色、亮度、背景和光照变化当作物理差异。
- C 证明当前多种指标对时序破坏并不可靠，即使数据本身是按物理规则生成的，指标也可能给出误导性排序。

#### Physics-IQ

- 数据集覆盖更广，但当前项目里的评测覆盖还不完整。
- 在只跑了 `1` 个 smoke case 的前提下，现有结果不足以支持方法层面的比较结论。

### 更稳妥的使用方式

- 用 `PDI` 看几何前端和局部结构是否稳定
- 用 `WMReward / V-JEPA` 看短窗未来预测是否一致
- 用 `Cosmos / VideoPhy-2` 看粗粒度语义与常识是否违和
- 强制保留 `B3` 外观鲁棒性检查和 `C` 时序打乱检查，先筛掉明显不稳的指标，再谈方法排名

当前项目里没有哪个单指标可以直接当作“客观物理正确性分数”。
