V-JEPA 2-AC 训练流程可视化

这个页面对应 app/vjepa_droid/train.py 的实际训练线。重点不是 mask 重建，而是 action-conditioned predictor 在 target latent 上做 teacher forcing 和短程 auto-regressive rollout，并用 latent L1 loss 训练。

输入视频: 854x480 原始帧数: 82 训练帧数: 8 patch/frame: 256 total tokens: 2048 encoder dim: 1408 predictor dim: 1024 auto_steps: 2 loss_exp: 1.0

主流程

1. clips
[1, 3, 8, 256, 256]
输入 8 帧视频，shape 是 [B, C, T, H, W]。
2. target encoder
[8, 3, 2, 256, 256] -> [1, 2048, 1408]
每帧被复制成 2 帧 tubelet 输入，编码成完整目标 latent h。
3. teacher forcing
[1, 1792, 1408] -> [1, 1792, 1408]
真实的 [0..6] 作为输入，预测 [1..7]。
4. rollout
[1, 512, 1408] -> [1, 512, 1408]
从 [0(real), 1(pred)] 继续滚到 2(pred)。
5. latent loss
jloss + sloss
两项都是 latent L1，对齐 target encoder 特征，不比较像素。

target encoder 看哪些帧

target encoder input frames = [0,1,2,3,4,5,6,7]
h.shape = [1, 2048, 1408]

完整 8 帧都被编码成目标 latent h。每帧有 256 个 patch token，所以总长度是 8 x 256 = 2048。

teacher forcing 输入哪些帧

predictor input = [0(real),1(real),2(real),3(real),4(real),5(real),6(real)]
z_tf.shape = [1, 1792, 1408]

teacher forcing 阶段输入真实的前 7 帧 latent，输出对齐到下一帧序列，即 [1(pred),2(pred),3(pred),4(pred),5(pred),6(pred),7(pred)]。

auto_steps=2 的 rollout 细化

第 1 步：构造 rollout 起点

_z = concat(z[:, :tokens_per_frame], z_tf[:, :tokens_per_frame])
shape = [1, 512, 1408]
语义 = [0(real), 1(pred)]

这里不是把整段 z_tf 都拿来滚，而是只取它的第一帧预测，也就是 1(pred)，和真实的 0(real) 拼成 rollout 的起点。

第 2 步：继续滚出 2(pred)

_z_nxt = _step_predictor(_z, actions[:, :2], states[:, :2], extrinsics[:, :2])[:, -tokens_per_frame:]
full predictor out = [1, 512, 1408]
last frame only = [1, 256, 1408]
语义 = 2(pred)

因为 auto_steps=2，循环只执行一次。输入是 [0(real),1(pred)]，最后一帧切出来就是 2(pred)。

最终 rollout 序列

_z = [0(real), 1(pred), 2(pred)]
z_ar = _z[:, tokens_per_frame:] = [1(pred), 2(pred)]
z_ar.shape = [1, 512, 1408]

训练里真正参与 sloss 的不是三帧，而是去掉第一帧 context 之后的两帧预测：[1(pred),2(pred)]。

jloss 和 sloss 各自比较什么

jloss: teacher forcing loss

z_tf = [1(pred),2(pred),3(pred),4(pred),5(pred),6(pred),7(pred)]
target = h[:, tokens_per_frame : z_tf.size(1) + tokens_per_frame]
target = [1(target),2(target),3(target),4(target),5(target),6(target),7(target)]
shape = [1, 1792, 1408]

jloss 监督 teacher forcing 输出整段下一帧预测序列，对齐到目标的帧 1 到帧 7。

sloss: rollout loss

z_ar = [1(pred),2(pred)]
target = h[:, tokens_per_frame : z_ar.size(1) + tokens_per_frame]
target = [1(target),2(target)]
shape = [1, 512, 1408]

这就是你问的那一项。sloss 比较的是 rollout 结果 [1(pred),2(pred)] 和 target encoder 编码得到的 [1,2] 两帧特征。

loss 公式

def loss_fn(z, h):
    _h = h[:, tokens_per_frame : z.size(1) + tokens_per_frame]
    return torch.mean(torch.abs(z - _h) ** loss_exp) / loss_exp

当前配置 loss_exp = 1.0，所以就是逐 token、逐通道的 L1 平均。对 sloss 来说，实际比较张量 shape 是 [1, 512, 1408] 对 [1, 512, 1408]。

predictor 内部 shape

输入与动作状态拼接

x in = [1, 512, 1408]
predictor_embed(x) = [1, 512, 1024]
view to [B, T, H*W, D] = [1, 2, 256, 1024]
concat action/state = [1, 516, 1024]

predictor 每帧除了 patch token，还会在帧前面插入 action token 和 state token，所以每帧内部长度从 H*W 变成 H*W+2。

输出

predictor_proj out = [1, 512, 1408]

predictor 最后会把 action/state token 再拆掉，只保留视频 patch token，并投影回 encoder latent 维度 1408。

loss 回传路径

前向

clips -> forward_target(clips) -> h
h -> forward_predictions(h) -> z_tf, z_ar
loss = jloss + sloss

这条训练线里，predictor 的输入直接就是 h，也就是 target encoder 产生的目标 latent。

不会回传到 target encoder

with torch.no_grad(): h = target_encoder(...)
for p in target_encoder.parameters(): p.requires_grad = False

target encoder 是冻结的，而且前向在 no_grad 里，因此 jloss/sloss 都不会回传到 target encoder。

会回传到 predictor

loss -> z_tf / z_ar -> predictor(...)
包括: predictor_embed, action_encoder, state_encoder, transformer blocks, predictor_proj

有梯度的是 predictor 全部内部参数，因为 loss 直接由 predictor 输出张量算出来。

当前代码里 encoder 也不吃梯度

train_step 没有调用 encoder(...)
loss 计算图里没有 encoder 分支

按当前 app/vjepa_droid/train.py 实现，student encoder 并没有参与这条前向，因此这一步训练里它也拿不到梯度。实际被训练的是 predictor，不是标准 JEPA 里的 encoder + predictor 联合更新。
